# 基于气象大数据的出行推荐系统 · 28 天逐日开发计划

> 修订版说明：对话模型采用「多提供商抽象层」，默认 DeepSeek，可通过配置切换通义千问 / 智谱 GLM / OpenAI / Moonshot / Ollama 等 OpenAI 兼容模型；向量维度固定 `Vector(1024)`；Docker 仅编排 PostgreSQL + Redis。
> 推进原则：**每天只完成对应天数任务，禁止超前开发未排期模块**；每阶段结束需输出 ✅ 检查清单，全部打勾才算完成。
> 使用方式：每天开发前打开对应 `Day N` 章节，完成后勾选 `- [x]`。

---

## 项目总览

| 维度 | 内容 |
| --- | --- |
| 落地场景 | 广州市气象大数据 + 3D 地理可视化 + AI 智能体 |
| 前端 | C 端 React19 + Vite + TS；B 端 Vue3 + Vite + TS |
| 后端 | Python FastAPI + SQLAlchemy 2.0 异步 ORM |
| 数据库 | PostgreSQL 17 + TimescaleDB + pgvector(1024) + PostGIS + Redis |
| AI | LangGraph + MCP + Skill + RAG；多模型对话（DeepSeek 等 OpenAI 兼容模型，默认 deepseek）+ 智谱 embedding-3 |
| 任务队列 | Celery + Redis |
| 交付目标 | 28 天 MVP 可运行版本，可写简历 + 面试演示 |

### 关键约束
- 各模型 API Key **仅存后端 `.env`**，禁止硬编码 / 暴露前端 / 提交 git。
- 对话模型仅接入「OpenAI 兼容格式」提供商（DeepSeek / Qwen / GLM / OpenAI / Moonshot / Ollama），不引入 Anthropic Claude 等不兼容适配器。
- 知识库向量字段固定 `Vector(1024)`，模型 `智谱 embedding-3`（dimensions=1024）。
- 所有 LLM/Embedding 调用必须 `try-except` 捕获网络异常、限流、超时，返回友好降级提示。
- 控制知识库文档数量，避免产生过多 API 费用。
